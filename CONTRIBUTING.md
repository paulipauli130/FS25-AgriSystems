# Contributing to FS25 AgriSystems

Thank you for your interest in contributing to FS25 AgriSystems!

AgriSystems is a community-driven modding project for Farming Simulator 25. Contributions, feedback and testing help improve the project.

## 1. Ways to Contribute

You can contribute in several ways:

- Report bugs and unexpected behaviour.
- Suggest new features or improvements.
- Test development versions.
- Improve documentation.
- Submit code changes.
- Help investigate compatibility issues.

## 2. Reporting Bugs

Before opening a new issue, check whether the problem has already been reported.

Please include:

- Farming Simulator 25 version.
- AgriSystems mod and version.
- A clear description of the problem.
- Steps to reproduce the issue.
- Relevant `log.txt` entries.
- Screenshots or other useful information.

Do not include personal information or unrelated log data.

## 3. Suggesting Features

Feature suggestions are welcome.

Please explain:

- What the feature should do.
- Why it would be useful.
- How it could work in gameplay.
- Whether it should be optional or configurable.

Large features should be discussed before implementation.

## 4. Pull Requests

Pull Requests are welcome for bug fixes, improvements and documentation.

Please follow these guidelines:

1. Keep changes focused on one issue or feature.
2. Use clear and descriptive commit messages.
3. Follow the existing code style.
4. Test your changes before submitting.
5. Document new configuration options and gameplay behaviour.
6. Explain what was changed and why.

Do not include unrelated changes in a Pull Request.

## 5. Development Guidelines

AgriSystems aims to follow these principles:

- Keep systems modular and configurable.
- Avoid unnecessary dependencies.
- Consider multiplayer behaviour.
- Avoid conflicts with other mods where possible.
- Keep performance in mind.
- Use clear and maintainable Lua code.
- Document important gameplay and technical decisions.

## 6. Compatibility and Testing

Changes should be tested in Farming Simulator 25 whenever possible.

If a change affects multiplayer, test both single-player and multiplayer behaviour.

Untested contributions must be clearly identified as such.

## 7. Communication

Please keep discussions respectful and constructive.

Different approaches and suggestions are welcome. Technical decisions should be based on maintainability, compatibility and gameplay quality.

## 8. License

By submitting a contribution, you agree that your contribution will be distributed under the project's MIT License, unless otherwise explicitly agreed.

Thank you for helping make AgriSystems better!
